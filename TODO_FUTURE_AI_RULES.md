# Future AI-Powered Financial Rules Engine

This document describes the planned evolution from the current **rule-based** allocation and coaching system to an **AI-powered** financial rules and coaching skill. All logic today is mocked and local; the following is a roadmap for when we integrate real AI and backend.

---

## 1. Personalized Allocation (Replace Static 50/30/20)

**Current state:** Fixed 50/30/20 default; user can only manually adjust percentages via chat.

**Future AI skill:**

- **Income-level awareness**  
  Suggest allocation bands by income tier (e.g. higher fixed costs at lower income → different needs %).

- **Spending history**  
  Use past months to propose realistic needs/wants/savings splits instead of a one-size-fits-all default.

- **Risk tolerance**  
  Optional user profile (conservative / balanced / aggressive) to nudge savings % and emergency-fund targets.

- **Fixed costs detection**  
  Identify rent, utilities, subscriptions, debt from transactions and set a “needs” floor; derive suggested wants/savings from the remainder.

**Replaceable components:**  
`FinancialRulesService.calculateTargets`, `defaultAllocation`, and any UI that shows “recommended” allocation. Replace with a call to an **AI allocation advisor** that returns personalized percentages and optional explanations.

---

## 2. Adaptive Learning (Beyond Static Rules)

**Current state:** Category → categoryGroup (needs/wants/savings) is hardcoded in the parser.

**Future AI skill:**

- **Recurring subscriptions detection**  
  Detect Netflix, Spotify, etc. over time and tag them; suggest a “subscriptions” sub-bucket and a realistic “wants” or “needs” share.

- **Realistic savings %**  
  Instead of assuming 20% is possible, infer from history (e.g. “You typically save 12%; we’ll target 15% next month”) and surface that in the rules engine.

- **Category reclassification**  
  Let the model suggest moving certain categories from “wants” to “needs” (or vice versa) based on behavior and user feedback.

**Replaceable components:**  
`MockParserService` category → categoryGroup mapping, and any logic that assumes a fixed savings target. Replace with an **adaptive categorization + allocation** service that learns from transactions and user corrections.

---

## 3. Behavioral Coaching (Patterns and Nudges)

**Current state:** Simple rule-based insight strings (e.g. “You saved less than target”, “Wants exceeded allocation”, “You stayed close to your plan”).

**Future AI skill:**

- **Pattern detection**  
  e.g. weekend spending spikes, post-payday splurges, or “small leak” clusters (repeated small amounts that add up).

- **Emotional / stress spending**  
  Optional signals (time of day, sequence of transactions) to detect likely emotional spending and suggest gentle nudges instead of only numeric targets.

- **Personalized nudges**  
  Replace fixed phrases with short, context-aware messages (e.g. “You’re 10% over on wants; most of it was food delivery this week”) generated by an LLM or a dedicated nudge model.

**Replaceable components:**  
`FinancialRulesService.insightFromEvaluation` and any “coach message” construction in the app. Replace with an **AI coaching / nudge service** that takes evaluation results + transaction context and returns a single insight or nudge message.

---

## 4. Dynamic Monthly Scoring (Beyond Simple % Match)

**Current state:** `evaluateMonth` uses a simple per-bucket score (actual vs target) and averages them into `performanceScore`.

**Future AI skill:**

- **Weights by priority**  
  e.g. savings shortfall penalized more than wants overage, or the reverse for a “debt payoff” mode.

- **Trends**  
  Compare this month to last month (improving vs declining) and factor that into the score or the message.

- **One-off events**  
  Allow marking or detecting one-off large expenses so they don’t distort the monthly score; optionally separate “recurring” vs “exceptional” in the evaluation.

**Replaceable components:**  
`FinancialRulesService.evaluateMonth` and the definition of `MonthEvaluationResult.performanceScore`. Replace with an **AI scoring model** that consumes income, targets, actuals, and optional context and returns a score + breakdown (and optionally a short explanation).

---

## 5. Integration Points (Where to Plug In AI)

| Current component              | Replace with (future)              |
|--------------------------------|------------------------------------|
| `FinancialRulesService`       | AI allocation + scoring service    |
| `MockParserService` (category) | AI categorization + categoryGroup |
| `InsightService` / coach text  | AI coaching / nudge API            |
| `MockSalaryService`           | Backend salary + allocation config |
| Rule-based “Target vs Actual”  | Same UI, data from AI evaluation   |

Keep the existing **contracts** (e.g. “get targets from income + allocation”, “evaluate month”, “get one insight message”) so that swapping the implementation from rule-based to AI does not require rewriting the UI or navigation.

---

## 6. Summary

- **Personalized allocation:** Income, history, fixed costs, risk tolerance → suggested needs/wants/savings.
- **Adaptive learning:** Recurring detection, realistic savings %, and category refinement.
- **Behavioral coaching:** Pattern and emotional-spending detection; personalized nudges instead of static sentences.
- **Dynamic scoring:** Priority-weighted, trend-aware, and optionally one-off-aware monthly score.

All of the above should remain **mocked and replaceable** until the real AI and backend are integrated. This file serves as the single reference for the future AI rules and coaching skill.
